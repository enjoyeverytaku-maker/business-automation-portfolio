1｜中堅企業・管理部門

Slack ワークフローの重複処理・通知漏れを根本から解決

課題　案件登録が集中すると同じ案件が重複処理され、通知漏れ・二重通知も起きていた。実データでは数千件中100件超の重複。

対応　ログを分析し、行が一度に追加されると別の行を読んでしまう構造的な原因を特定。「変更を待って反応する」方式から「1分ごとに新しい行を見に行く」方式に変え、失敗した分は自動で再試行。同じ案件の重複は営業担当に Slack でお知らせする形に。切り戻し手順書も作成。

応急処置を即日で本番反映。kintone 連携版の構築・テストまで行い、継続のご依頼につながりました

Google Apps Script / Slack Workflow Builder / Slack API / kintone REST API（連携版）

仕組み

  1. Slack の登録フォームから案件を登録
  2. スプレッドシートに1行追加
  3. GAS が1分ごとに新しい行だけを確認同時に動かないようロック／失敗した行は次回に再試行
  4. テンプレートから帳票を作成し、URL と処理状況を記録
  5. Slack で担当者に通知

同じ「案件ID＋取引先」が来たら、処理は止めずに営業担当へ DM でお知らせ

2｜中堅企業・情報システム

GAS の変更を「セーブ」して戻せる社内向け変更管理システム

課題　業務で GAS を多数使っているが、変更前との差分確認や元に戻す手段がなく、修正ミスが怖くて手を入れられない状態。

対応　ブラウザだけでソースの取得・差分表示・セーブ・ワンクリック復元・変更の承認ができる仕組みを、お客様自身の Google Cloud 上に構築。操作マニュアル・管理者ガイド・検収チェックリストを作成。

納品・検収完了。エンジニアでない担当者が GAS の変更を管理できるようになりました

3｜中堅企業・経理部

メールで届く請求書 PDF をフォルダへ自動保存

課題　取引先から共有アドレスに届く請求書を、担当者が毎回ダウンロードして保存していた。

対応　添付 PDF を宛先アドレスごとに決めた Google ドライブのフォルダへ自動保存する GAS を作成。保存先はコードを触らず設定画面から1行ずつ登録できる形にし、社内の担当者が自分で設置できる手順書を用意。

経理部で稼働中。担当の方から「かなり楽になった」とのお声をいただいています

Google Apps Script / Gmail / Google ドライブ

仕組み

  4. メールに「処理済み」ラベル。判断できないものは「要確認」へ

4｜中堅企業・全社

部署ごとの申請・承認ワークフローの基盤構築

課題　部署ごとにバラバラだった申請・承認を、共通の仕組みで回したい。申請内容は後から案件単位で追えるようにしたい。

対応　申請の入口となる親ワークフローと中央の管理表を構築し、申請IDで kintone と紐づける設計に。法務部門の申請12種類は、差し戻しの可否・回数・再入力の範囲を事前に質問して確定させてから設計しました。

基盤を納品。各部署への展開はお客様側の方針に合わせて進めています

Slack Workflow Builder / Google スプレッドシート / Google Apps Script / kintone

仕組み

  1. Slack の共通申請フォームから申請
  2. 中央の受付シートに記録
  3. GAS が1分ごとに経路表と申請者の役職を確認し、申請IDを発行
  4. 部署別の承認ワークフローへ振り分け
  5. 一次・二次・最終承認（Slack のボタンで承認／差し戻し）
  6. 申請IDをキーに kintone へ記録

6｜福祉・介護サービス法人

複数口座の出納帳から資金繰り表を自動作成

課題　金融機関・支援機関に出す資金繰り表を、複数口座の出納帳から毎月手作業で作っていた。

対応　科目の対応表で自動仕分けし、日繰り資金繰り表と月次推移表を自動作成。予定と実績を色分けして二重計上を防ぎ、通帳残高との差異も自動チェック。

納品後も科目の追加・並び替え機能などの追加要望に対応しています

Google Apps Script / Google スプレッドシート

仕組み

  1. いつもの出納帳（口座ごと）はそのまま
  2. 科目の対応表（キーワード→集計科目）で自動仕分け
  3. 月ごとの日繰り表へ。出納帳を同期すると予定が実績に置き換わる
  4. 月次まとめを更新し、通帳残高との差異をチェック

FAQ

よくある質問

どんな案件に対応できますか？

スプレッドシート・Google Apps Script の自動化、kintone・Slack ワークフローの構築と改修、会計クラウドの初期設定・連携、Excel VBA の改修が中心です。「こんなときにご相談ください」の一覧に近いものがあればお気軽にどうぞ。

常駐・出社は可能ですか？

リモートワーク専門のため、常駐・出社が必要な案件はお受けできません。

見積もりはどのように出しますか？

ヒアリング後に要件を整理し、工数×単価でお見積りします。概算が必要な場合は案件内容をお聞きした上でお伝えします。

小さい案件（数千円規模）も対応できますか？

最低受注金額は設けていませんが、ヒアリング・仕様確定のコストを考慮し、¥10,000以上を推奨しています。

開発期間の目安は？

小規模（1〜2機能）で2〜5営業日、中規模（複数機能連携）で5〜10営業日が目安です。急ぎの場合はご相談ください。

ソースコードは納品してもらえますか？

はい、全コードを納品します。著作権はクライアント様に帰属します。

納品後にバグが見つかった場合は？

納品後3日以内の不具合修正は無償です。期間後は別途お見積りします。

引き継ぎ資料はありますか？

セットアップ手順・操作マニュアル・トラブルシューティングを必ず同梱します。IT知識がない担当者でも運用できる粒度を心がけています。

対応できないことはありますか？

常駐・出社が必要な業務、フルタイム拘束（週30時間以上）の案件はお受けできません。またインボイス（適格請求書）の発行には対応しておりません（未登録のため）。
